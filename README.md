# mailbot

Модуль для качественных почтовых рассылок через **Яндекс Почту** (обычную и Яндекс 360 на своём домене) и **любую доменную почту** по SMTP. Массовая отправка, планирование, лимиты, отписки, обработка недоставки, проверка DNS домена.

Это библиотека на Python с минимальным CLI для запуска воркера. Интерфейса (веб / Telegram) пока нет — он будет надстройкой над тем же API: `from mailbot import MailBot`.

## Что умеет

| Область | Что сделано |
|---|---|
| **Ящики** | Пресеты `yandex`, `yandex360`, `custom` (любой SMTP: Mail.ru для бизнеса, хостинг, свой Postfix). Пароли шифруются (Fernet) |
| **Контакты** | Списки, импорт CSV (разделитель `,` `;` табуляция определяется сам, русские заголовки, BOM, cp1251), произвольные поля для подстановки |
| **Шаблоны** | Jinja2 в песочнице. Необъявленная переменная — **ошибка**, а не пустое место: письмо не уйдёт как «Здравствуйте, !» |
| **Планирование** | Запуск в нужное время (по умолчанию `Europe/Moscow`), пауза / возобновление / отмена, тестовая отправка себе |
| **Лимиты** | Скорость (писем/мин) и суточный лимит на ящик — скользящие 24 часа, общие для всех кампаний ящика |
| **Надёжность** | Повторы с нарастающей задержкой, автопауза при неверном пароле или блокировке, защита от дублей при падении процесса |
| **Отписки** | Подписанные ссылки, `List-Unsubscribe` + one-click (RFC 8058), WSGI-обработчик. Отписанные никогда не возвращаются импортом |
| **Недоставка** | Жёсткие отказы SMTP и отчёты о недоставке (DSN) из ящика по IMAP — «мёртвые» адреса исключаются автоматически |
| **Доставляемость** | Письмо `multipart/alternative` (HTML + текст), `Message-ID` на вашем домене, `Precedence: bulk`, проверка SPF/DKIM/DMARC |

## Быстрый старт

```bash
git clone https://github.com/Qwertyuiop09876/Mail_bot && cd Mail_bot
make install                 # venv, зависимости, pre-commit
source .venv/bin/activate    # дальше команда `mailbot` доступна без префикса (в новом терминале — снова)
cp .env.example .env
mailbot gen-key              # вставьте результат в MAILBOT_SECRET_KEY
```

В `.env` заполните `MAILBOT_SECRET_KEY` и `MAILBOT_UNSUBSCRIBE_BASE_URL` (публичный HTTPS-адрес сервера отписок, см. ниже). Без адреса отписки кампанию запланировать нельзя — это сознательное ограничение.

### Яндекс: что нужно сделать и что может помешать

Нужно от вас: **адрес ящика**, **пароль приложения** и понимание, какой у вас ящик — личный `@yandex.ru` или на своём домене в Яндекс 360 (от этого зависят логин, лимиты и доступность).

1. **Пароль приложения** с типом «Почта»: Яндекс ID → Безопасность → Пароли приложений. С 5 мая 2023 пароль аккаунта сторонним программам не подходит. Новый пароль иногда начинает работать не сразу (в справке до 2–3 часов). Он сбрасывается при восстановлении доступа и при «Выйти на всех устройствах» — тогда `mailbot account-password NAME`.
2. **Две галочки** в Почта → Все настройки → Почтовые программы: «С сервера imap.yandex.ru по протоколу IMAP» и «Пароли приложений и OAuth-токены». IMAP нужен и для входа, и для чтения отчётов о недоставке.
3. **Новый ящик** один раз откройте в браузере и примите пользовательское соглашение, иначе вход даёт `535 5.7.8 … Please accept EULA first`.
4. **Логин:** для ящика на домене — полный адрес. Для личного ящика справка называет имя до `@`; на практике пробуют оба (`--login имя`).
5. **Адрес отправителя должен совпадать с логином** (в справке Яндекса — «полностью соответствовать»), иначе `553 5.7.1 … not owned by auth user`. `account-add` предупредит о расхождении.
6. Защита Яндекса может временно заблокировать аккаунт (чаще — нет привязанного телефона): тогда не работают и пароли приложений, обычно ~пару часов.

> **⚠ Главный риск, который я не смог проверить.** По сообщениям СМИ (Хабр, CNews) и письму сервиса Saby от 11.06.2026, с **29.06.2026** Яндекс закрыл доступ по IMAP/SMTP/POP3 для ящиков **без платного тарифа Яндекс 360**. Для ящиков организаций на своём домене это, судя по всему, действует. Для личных `@yandex.ru` источники противоречат друг другу (поддержка по пересказам говорит, что не затронуты; другие издания — что затронуты). Официальной страницы найти не удалось (доступ к yandex.ru из окружения закрыт), подтверждений «после 29 июня» нет. **Единственный надёжный способ узнать — `mailbot account-add` с вашим ящиком.** Если пункты 1–6 в порядке, а вход не проходит, то для ящика на своём домене причина, вероятно, в тарифе; для личного это возможно, но не доказано.

#### Добавить ящик

На машине, где будет работать воркер (там живёт база, см. «Развёртывание»):

```bash
mailbot account-add main --provider yandex --email ваш@yandex.ru --from-name "Имя отправителя"
# для домена на Яндекс 360:  --provider yandex360 --email news@вашдомен.ru
```

Пароль спросят скрытым вводом (в аргументах его принимать нельзя: он остался бы в истории shell). Ящик сохраняется, **только если вход удался**; иначе выводится чек-лист выше. Для скриптов: `--password-env VAR` (задавайте переменную так, чтобы пароль не попал в историю: `read -rs VAR && export VAR`). Посмотреть список — `mailbot accounts`, заменить пароль — `mailbot account-password NAME`. Никогда не присылайте пароль в чат и не коммитьте его.

### Сценарий целиком

Полный сценарий — [`examples/quickstart.py`](examples/quickstart.py), он проверяется тестом. Ниже его сокращённая версия для ящика, уже добавленного командой выше:

```python
from datetime import datetime
from mailbot import MailBot

with MailBot() as bot:  # читает .env; ящик "main" уже добавлен через `mailbot account-add`
    bot.init_db()
    print(bot.accounts.check_connection("main"))  # вход в SMTP без отправки

    bot.contacts.import_csv("contacts.csv", list_name="clients")
    bot.templates.save(
        "october",
        subject="Новости, {{ first_name | default('друг') }}",
        html="<p>Привет, {{ first_name | default('друг') }}!</p>"
        "<p>Письмо отправлено на {{ email }}. <a href='{{ unsubscribe_url }}'>Отписаться</a></p>",
    )

    c = bot.campaigns.create("Октябрь", account="main", lists=["clients"], template="october")
    print(bot.campaigns.validate(c.id))  # ошибки и предупреждения заранее
    bot.dispatcher.send_test(c.id, "me@example.com")  # письмо глазами получателя
    bot.campaigns.schedule(c.id, datetime(2026, 10, 12, 10, 0))  # 10:00 по Москве
```

Дальше — два долгоживущих процесса:

```bash
mailbot run                 # воркер: отправляет по расписанию с учётом лимитов
mailbot serve-unsubscribe   # ссылки отписки (за nginx/Caddy с HTTPS)
```

Остальные команды: `account-add` / `accounts` / `account-password`, `status` (ход кампаний), `check-account NAME`, `scan-bounces NAME`, `check-domain DOMAIN --provider yandex360`, `run --once` (для cron).

### Первый боевой прогон (проверьте это руками)

Часть допущений проверена только на локальном SMTP-сервере, поэтому на вашем ящике сделайте так:

1. `mailbot account-add …` → вход прошёл.
2. `print(bot.dispatcher.send_test(campaign_id, "другой@ящик.ru"))` — вернёт наш `Message-ID`. В письме откройте «Показать оригинал» и проверьте: **сохранился ли этот `Message-ID`** (на нём держится сопоставление отчётов о недоставке — если Яндекс его переписывает, `scan-bounces` ничего не сопоставит и вернёт `не наши`) и есть ли `List-Unsubscribe`/`List-Unsubscribe-Post`. Ссылка отписки в тестовом письме — заглушка и ничего не отписывает.
3. Маленькая кампания на 3–5 своих адресов, затем `mailbot scan-bounces NAME`: убедитесь, что IMAP-вход работает.
4. Только потом — реальный список.

### Шаблоны

Доступны `{{ email }}`, `{{ first_name }}`, `{{ last_name }}`, `{{ name }}`, `{{ unsubscribe_url }}` и все остальные колонки CSV (`{{ город }}`). Имя, которого нет у контакта, считается **неопределённым**: пишите `{{ first_name | default('друг') }}`, иначе проверка при планировании покажет, у каких адресов нет данных. Текстовая версия письма делается из HTML автоматически, если не задана своя.

## Чтобы письма не попадали в спам

Код делает свою часть (заголовки, лимиты, отписки, исключение «мёртвых» адресов), но репутация зависит и от вас:

1. **SPF, DKIM, DMARC** на домене отправителя — `mailbot check-domain example.com --provider yandex360`. Для Яндекса DKIM-селектор обычно `mail`.
2. **Только согласившимся.** Рассылка по купленным/собранным без согласия базам быстро убивает репутацию домена (и может нарушать закон о рекламе).
3. **Прогрев.** С нового домена начинайте с десятков–сотен писем в день и растите постепенно: `bot.accounts.set_limits("main", daily_limit=100)`.
4. **Чистая база.** Раз в день-два запускайте `mailbot scan-bounces main`, не возвращайте отписавшихся.
5. Видимая ссылка отписки в подвале — `validate()` предупредит, если её нет.
6. **Свой домен для рассылок**, а не основной адрес компании: проблемы с репутацией не заденут обычную переписку.
7. **Требования Яндекса к рассылкам** (по его справке): DKIM-подпись и SPF обязательны; `List-Unsubscribe` с отпиской в один клик (есть), отписка без регистрации и в течение 10 минут (ссылка работает мгновенно), `Precedence: bulk` (есть), **адрес получателя в тексте письма** — поставьте `{{ email }}` в подвал (`validate()` напомнит). DMARC у Яндекса только рекомендован.

### Лимиты и блокировки Яндекса

| Ящик | Предел в сутки | Пресет |
|---|---|---|
| Личный `@yandex.ru` | 300 получателей по SMTP (русская справка) или 500 (старая английская) | `yandex`: **300** |
| Яндекс 360, свой домен | 3000 внешних получателей на ящик и **5000 на весь домен** | `yandex360`: 3000 |

Считаются получатели, а не письма; лимиты нельзя поднять, а антиспам может снизить их раньше при однотипных рассылках. Цифры собраны из пересказов справки (сама страница из окружения была недоступна) и местами расходятся — **сверьте их** и при необходимости задайте свои: `bot.accounts.set_limits("main", daily_limit=…)`. Если на домене несколько ящиков-отправителей, учитывайте общий потолок домена.

**Блокировка за спам.** По справке Яндекса, если ящик признан источником спама или исчерпан лимит, отправка блокируется на 24 часа; блок снимается сам, только если за это время не пытаться отправлять письма, иначе продлевается ещё на сутки. Ответ `554 5.7.1 … Message rejected under suspicion of SPAM` может означать и блок ящика, и отказ по содержимому одного письма — по тексту это не отличить (справка советует отправить одно обычное письмо из веб-интерфейса). Поэтому на такой ответ mailbot осторожно останавливает все кампании ящика, в том числе запланированные, уже после *первого* отказа и не теряет получателей. Возобновляйте (`campaigns.resume`) не раньше чем через сутки, проверив текст письма, SPF и DKIM. Что именно этот ответ продлевает блок при повторах, прямо не подтверждено — это осторожное допущение. Яндекс также пишет, что личный ящик не предназначен для рассылок (для них — Яндекс 360 или «Яндекс Рассылки»), а массовая отправка на несуществующие адреса сама ведёт к блокировке — поэтому `550 5.7.1 No such user!` исключает адрес из базы сразу.

## Как это устроено

```
src/mailbot/
  app.py          MailBot — единая точка входа, собирает сервисы
  models.py       SQLAlchemy-модели (время везде UTC), db.py + migrations/ (Alembic)
  accounts.py     ящики и подключение     providers.py  пресеты
  contacts.py     контакты, списки, CSV   templates.py  шаблоны
  campaigns.py    жизненный цикл кампании: validate → schedule → pause/resume/cancel
  dispatcher.py   движок отправки: лимиты, повторы, предохранители, восстановление
  rendering.py    Jinja2 + HTML→текст     message.py    сборка MIME-письма
  smtp.py         SMTP и классификация ответов сервера (4xx / 5.1.1 / 5.7.x ...)
  unsubscribe.py  подписанные ссылки + WSGI   bounces.py  разбор DSN по IMAP
  dnscheck.py     SPF / DKIM / DMARC          cli.py       команды для запуска
```

```
draft ─schedule→ scheduled ─(время пришло)→ sending ─→ completed
                    │                          │  ▲
                    └──── pause / ошибка ящика ┴→ paused ─resume→ …      cancel → cancelled
```

Гарантии, на которые можно опираться:

- **Не больше одного письма на получателя.** Запись о доставке помечается «отправляется» *до* вызова SMTP. Если процесс упал в этот момент, она станет `failed` («состояние неизвестно») и не будет отправлена повторно сама — дубль рассылки хуже редкой потери. Решение вернуть такие письма в очередь — за вами: `campaigns.retry_failed(id)`.
- **Отписка действует сразу.** Статус контакта проверяется в момент отправки, а не только при планировании.
- **Ошибки ящика не сжигают базу.** Неверный пароль или «отправитель не разрешён» ставят кампанию на паузу, не тратя попытки получателей; серия отказов по содержимому — тоже пауза; недоступный сервер — отсрочка для ящика.
- **Фоновая обработка**: один воркер на базу. Запускать два одновременно нельзя.

## Развёртывание (пример)

`/etc/systemd/system/mailbot.service`:

```ini
[Service]
User=mailbot
WorkingDirectory=/opt/mailbot
EnvironmentFile=/opt/mailbot/.env
ExecStart=/opt/mailbot/.venv/bin/mailbot run
Restart=always
```

Сервер отписок слушает `127.0.0.1:8080`, nginx/Caddy терминирует HTTPS и проксирует `location /unsubscribe/` на него (путь не переписывать). Для нагрузки подойдёт любой WSGI-сервер с `MailBot().unsubscribe_app()`.

Резервные копии: файл базы (`data/mailbot.db`) и `MAILBOT_SECRET_KEY` — без ключа сохранённые пароли ящиков не расшифровать.

## Чего пока нет

Отслеживания открытий/кликов (открытия ненадёжны после Apple Mail Privacy Protection, клики потребуют публичного редиректа); обработки жалоб (FBL); окон отправки по времени суток; вложений и встроенных картинок; отписки через `mailto:`; A/B-тестов; поддержки нескольких воркеров и PostgreSQL (модели совместимы, но не проверялись). Интерфейс пока не сделан намеренно. Не проверено на живом Яндексе: сохранение `Message-ID`, формат и папка отчётов о недоставке, точный текст ответа при превышении суточного лимита (классификатор знает семейство «spam limit»/«suspicion of spam»), аутентификация OAuth (XOAUTH2) — сейчас только пароль приложения.
