# mailbot — заметки для разработки

Python 3.11+, src-layout (`src/mailbot`), SQLAlchemy 2 + SQLite, Alembic, Jinja2, stdlib `smtplib`/`imaplib`. Документация для пользователя — `README.md`.

## Команды

```bash
make install     # venv + dev-зависимости + pre-commit
make check       # ruff check/format --check, mypy (strict), pytest — как в CI
.venv/bin/pytest tests/test_dispatcher.py -k daily    # один тест
make migrate-new MSG="..."                             # миграция после правки models.py
```

В облачных сессиях окружение готовит `.claude/hooks/session-start.sh` (venv в `.venv`, `PATH` уже настроен).

## Архитектура в двух словах

`MailBot` (`app.py`) собирает сервисы над одним `Database`. Сервисы открывают короткие транзакции (`db.session()`), возвращают ORM-объекты (`expire_on_commit=False`), без ленивых связей снаружи. Отправка — только в `dispatcher.py`; всё, что ходит в сеть, идёт через `Transport` (`smtp.py`) и внедряется фабрикой — поэтому тесты не трогают сеть.

## Инварианты — не ломать

- **At-most-once.** Доставка помечается `sending` и коммитится *до* вызова SMTP; зависшие `sending` становятся `failed`, а не `pending`. Не «чините» это повтором — дубль письма хуже потери.
- **Подавление.** Контакт не `active` не получает писем; импорт и `add()` никогда не меняют статус. Вернуть можно только `resubscribe(reason=...)`. Статус проверяется ещё раз при отправке.
- **Время — только UTC aware.** Колонки через `UTCDateTime`; наивные `datetime` отвергаются. Наивный ввод пользователя трактуется в `Settings.timezone` (только в `CampaignService._to_utc`).
- **«Сейчас» — только из внедрённых часов.** Сервисы и диспетчер получают `clock` (`MailBot(clock=...)`); в логике не вызывайте `utcnow()` напрямую, иначе расписание и лимиты разойдутся с часами теста. `Delivery.updated_at` специально без `onupdate`: каждая запись ставит его сама. `tests/test_clock_independence.py` гоняет сценарий с часами в 2001 и 2099 годах — он ловит любое обращение к реальному времени.
- **Секреты.** Пароли ящиков хранятся зашифрованными (`SecretBox`), в логи и тексты ошибок не попадают. `.env`, `data/`, `*.db`, ключи — в `.gitignore`; не коммитить.
- **Шаблоны строгие.** `StrictUndefined`; `first_name`/`last_name`/`name` в контексте только если непустые — иначе `default()` не сработает. Тема очищается от переводов строк (инъекция заголовков).
- **Классификация ответов SMTP** (`smtp.classify_smtp_error`): `RecipientRejected` → контакт `bounced`; `MessageRejected` → ошибка без подавления; `AccountError` → пауза кампаний ящика, получатель остаётся в очереди; `Transient` → повтор. Меняя таблицу, добавляйте строку в `tests/test_smtp.py` — желательно с реальным текстом сервера. Из исследования Яндекса (источники — пересказы справки, живого теста не было):
  - `550 5.7.1 No such user!` — это неизвестный получатель под кодом политики: текст «нет такого пользователя» бьёт семейство `5.7.x`, иначе мёртвые адреса не исключаются, а Яндекс сам блокирует ящик за рассылку на несуществующие адреса;
  - `554 5.7.1 … suspicion of SPAM` / `Blocked by spam statistics` / `spamsource.mail.yandex.net` — блокировка *отправителя* на 24 ч, **каждая попытка продлевает её**: поэтому `AccountError` (стоп с первой попытки, никого не теряем), а не `MessageRejected` на каждого получателя;
  - `550 5.7.1 Policy rejection on the target address` — смысл не подтверждён (может быть репутационный отказ), поэтому подавлять адрес с первого раза не стали;
  - `552 5.2.2 Mailbox size limit exceeded` — полный ящик получателя: мягкая ошибка, контакт остаётся.
- **Баунсы по IMAP доверяем только при совпадении `Message-ID` и адреса** с нашей доставкой — иначе поддельный DSN отпишет любого.
- **Схема меняется только миграцией.** Правите `models.py` → `make migrate-new` → проверьте файл руками. `tests/test_migrations.py` падает, если модели и миграции расходятся. Не редактируйте применённые миграции.

## Известные неизвестные (Яндекс)

Проверено только по пересказам справки, **не** на живом ящике: сохраняет ли `smtp.yandex.ru` наш `Message-ID` (на нём держится доверие к отчётам о недоставке), формат и папка DSN, точный текст ответа при превышении суточного лимита, действует ли с 29.06.2026 требование платного тарифа Яндекс 360 для личных `@yandex.ru` (для доменных — похоже, да). Лимиты: личный 300 (SMTP) / 500, Яндекс 360 — 3000 на ящик и 5000 на домен. Не выдавайте эти пункты за установленные факты в документации.

## Соглашения

- Код, докстринги, исключения, логи — по-английски; README, справка CLI и страница отписки (её видит получатель) — по-русски.
- `mypy --strict`, `ruff` (правила в `pyproject.toml`); `assert` допустим для сужения типов.
- Тесты: `filterwarnings = error` — `ResourceWarning` (незакрытый сокет/соединение) роняет тест, это сознательно и уже поймало реальную утечку. Фикстуры `env`/`make_env` дают `MailBot` с in-memory SQLite, фейковым транспортом, управляемыми часами и записью `sleep`.
- Все операции с расписанием и лимитами тестируйте через `FakeClock`, не через реальное время.
- Новое поведение — с тестом. Примеры в `examples/` проверяются `tests/test_examples.py`.

## Что не делать без запроса

Интерфейс (веб/бот) — пока сознательно не делаем. Не добавляйте трекинг открытий/кликов, несколько воркеров и сторонние сервисы рассылок без отдельного решения.
